advc — language reference

Reference: actors & the world

The screen is a stack of actors in layers; the player interacts through the mouse; the room is panned by the camera. This chapter is the specification of those commands. Scripts and blocks are Control flow; text and panels are [Reactive UI(../reactive-ui.md); sounds and images on disk are Assets & fonts.

actor — a thing on screen

actor background, pos 0 0, z 0, image 0 0 0 room_bg, enable, mouse::over false

actor deskPapers, pos 174 156, z 1.5, image 0 0 0 desk_papers, enable
    mouse::area "image0"
    mouse::click clickPapers

actor detective, pos 60 340, z 3, walkat officewalk walkDetective,
    pose poseDetective, mouse::over false
    image 0 -36 -156 det_stand_e
    say::color white, say::pos 320 30
    vel 100
    enable
    inside officewalk depth scaleDetective
    lipsync lips_detective

One line: actor <name>, <properties…> (comma-separated), then indented sub-commands that configure it further. Actors may also be declared anywhere a command is (in a running script or an anim frame): the line creates the actor and applies the properties.

An actor’s images live in numbered layers: image <n> <dx> <dy> <image> installs image n at a pixel offset from the actor’s position; noimage <n> clears it. Sprites, props, mouth and blink layers — all on one actor. An anim typically swaps layer contents frame by frame (Animations).

tint and scale

tint <r> <g> <b> multiplies the selected actor’s colours, on every image layer: 1 leaves a channel as painted, 0.5 halves its light, above 1 brightens it. It is in linear light, like lighting — put a character in a dark corner with tint 0.4 0.4 0.45. With a duration, tint 0.7 0.4 0.45 600ms moves there from the colour now shown over that time. Asking for a colour already being faded to changes nothing — so an inside function can call tint every frame without restarting the fade.

scale <number> multiplies the actor’s rendered size around its position.

Both combine with the actor itself: they act on the currently selected actor — select <name> first (below).

Image transforms

image takes one optional trailing transform:

image <n> <dx> <dy> <image> [<transform>]

It mirrors / rotates / scales / skews that one layer’s image about its own rect center (CSS’s transform-origin default — the sprite stays anchored, only the pixels move). A directional character therefore needs its east art only; the west views re-reference it mirrored:

anim det_walk_w
    duration 1
        image 0 -36 -156 det_walk_e_0 flipx
        noimage 1
    ...

Two written forms: a bare sugar word, and a quoted chain of functions (the comma and/or space separated list composes exactly like a CSS transform list — the last function applies to the sprite’s own space first):

image 0 0 0 box flipx
image 0 0 0 box "rotate(90deg)"
image 1 244 302 bottle "rotate(20deg) translate(4px, -6px)"
image 3 60 220 sign "skewX(-12deg) scale(0.95)"
FunctionMeaning
translate(tx[, ty]) / translateX / translateYOffset in canvas px (px suffix optional)
scale(s[, sy]) / scaleX / scaleYFactor about the image center
rotate(a)Any angle, deg required
skew(ax[, ay]) / skewX / skewYShear, deg
matrix(a, b, c, d, e, f)Full affine, CSS column pairs
matrix3(a … i)A raw 3×3 — the last row included
flipx, flipy≡ scaleX(-1) / scaleY(-1)
rot45 … rot315 (45° steps)≡ rotate(NNdeg)

The layer’s hitbox follows the transform: the hit rect is the AABB of the transformed corners (flips and quarter turns stay exact; diagonals give the rotated box), and clicks still land where the pixels are. The transform is saved with the layer, so it survives save/load. Two honest caveats: rotates/skews that are not 90° multiples alias on pixel art (the sprite sampler is nearest-neighbor), and a matrix3 with a non-affine last row renders through a perspective divide — the engine shows whatever you write, but a degenerate last row (0 0 0) draws nothing and makes the image unclickable.

inside — the walk map drives behavior

A walk map (assets/<map>.json) is named rectangles over the floor, each optionally carrying numbers:

"rects": [
  {"name": "depth", "points": [0, 250, 960, 352], "args": [1.0, 1.15]},
  {"name": "lightDoor",   "points": [0, 250, 115, 352],  "args": [0.36, 0.35, 0.39]},
  {"name": "lightWindow", "points": [115, 250, 350, 352], "args": [0.68, 0.39, 0.44]}
]

inside <map> <rect> <func> registers on the selected actor: every frame its position sits in the rect, <func> runs with $1/$2 = its position across the rect (0..1, left→right / top→bottom) and $3..$5 = the rect’s first three numbers. Nothing runs on leaving, so the last call stays in effect — light zones should cover the whole floor.

Depth scaling and room light are both made this way:

func roomLight
    select detective
    inside officewalk depth scaleDetective
    inside officewalk lightDoor lightDetective
    inside officewalk lightWindow lightDetective

func scaleDetective
    $scale = 1 + ((1.15 - 1) * $2), scale $scale

func lightDetective
    tint $3 $4 $5 600ms

select — the active actor

tint, scale, talk and play act on the currently selected actor. select <name> sets it; pass an actor name instead where you prefer: camera::follow detective takes the name directly. An actor name is a checked value:

error: `f` reads `$1` as an actor: no `actor detevtive`

camera — rooms bigger than the window

camera::bounds 960 352      // the world's size; the camera stays inside it
camera::follow detective    // half-screen scroll after that actor
camera::at 0 0              // jump the view's top-left to (x, y)
camera::pan 320 0 1s        // move there over 1s (async: wait camera::pan …)

Without camera::bounds, the world is the canvas and the camera never moves. World-space actors (any without hud), walk maps, inside rects and walkto targets are all in world pixels; clicks are converted to world pixels for world actors and walking. camera::follow none stops following; the follow scroll is the half-screen step: past 4/5 of the view the room slides right, before 1/5 it slides left (0.6 s, eased).

The mouse

CommandMeaning
mouse::icon <image> <idle-image> <hx> <hy>Set the cursor: an image with a hotspot, and the idling image that replaces it.
mouse::active [<Bool>]false ignores the player’s clicks on actors, the floor (no walking) and non-modal panels — a cutscene holds the world; the pointer stays. Modal panels and open option menus stay clickable; no argument means true.
mouse::over <Bool>(on an actor) hover on/off.
mouse::area <image>(on an actor) the click hitbox.
mouse::click <func>(on an actor) the click handler.

Where a left click lands is decided in order, topmost first: an open option menu (it swallows every click while up); modal panels; non-modal panels (a miss falls through); then the world — the highest-z clickable actor whose pixels (or mouse::area box) carry the click, otherwise walking to that spot.

Callbacks run with no arguments — the function owns the response (which verb is selected is a variable the panel wrote; click position needs none in the classic verb model). The clickable elements of ui panels do receive values — $1 = the solidity of the clicked pixel, $2 = a grid item’s index (see [Reactive UI › Click dispatch(../reactive-ui.md#click-dispatch)) — and inside and walk-cycle callbacks receive positional values as documented above.

say — captions

select detective
say "Frank Malone. Detective." 2s

say "<text>" <duration> draws a caption near the actor (the actor’s say::color / say::pos / say::follow decides where it draws) for the duration, then removes it. Several actors can speak at once. For spoken lines with voice and visemes, use voice/talk — Animations & voice.

print, stopall

print "<text>" writes to the console (handy in tests). stopall halts every script the game has running except the calling one — reset the stage before a scripted beat.
