advc — language reference

Reference: testing & scripted play

A built game can be driven from its standard input: clicks, waits, screenshots and video. A script of these lines plays the game by itself — to watch it, to record it, or as an end-to-end test. Every sample game ships a walkthrough.play that plays it completely on its own.

ADVC_STDIN=1 ./target/debug/my-game < walkthrough.play                  # in its window
ADVC_HEADLESS=1 ADVC_STDIN=1 ./target/debug/my-game < walkthrough.play  # no window, as fast as it can run

ADVC_SEED=<n> fixes the random choices (random arms, dice) so runs repeat.

How lines run

Every line goes into a queue the game runs each frame, in order. Most lines take effect at once; a wait … line holds the queue until its condition is true, so the lines after it run only then. Time is game time: nothing counts down while the game is paused, so scripted waits are reproducible however busy the machine is.

If a wait isn’t satisfied within its timeout (2 minutes unless it says timeout=…), or a click target can’t be found, the script fails: the error is printed with its line number and the game exits with status 1.

# starts a comment (a # inside quotes is text).

Commands

LineDoes
click <x> <y>A left click at a canvas point (canvas-size space). In the window, a click on nothing walks there.
rclick <x> <y>A right click.
click actor <name>Clicks the actor where it takes the click: inside its hit area, on screen, not covered by another actor or a panel. Fails if it is off screen.
click ui <name>Clicks a ui element: an image by its click func or image name, a text label or option::show item by its text ("What happened here?" — the whole text first, then a text containing it).
wait idleUntil the player has control: the mouse is active (or a menu waits for a pick), nobody is walking, nothing is being said — for 300 ms and 5 frames in a row.
wait <duration>wait 2s, wait 500ms, wait 1min.
wait say "<text>"Until a line containing the text is on screen.
wait said "<text>"Until such a line has been on screen and is gone.
wait var <path> <op> <n>Until a variable compares true: ==, !=, <, <=, >, >= (an unset variable reads 0).
wait ui <def> hovered/leftUntil the cursor is over (mirror: over no element of) an open instance of the def — a button quad or a clickable/menu text label. Released already when the cursor’s state matches at the arm (an earlier batch’s move is the same as an earlier batch’s var write), and re-checked per tick.
wait ui <def> opened/closedUntil the def has (mirror: has no) an open instance. The same contract: the level at the arm, or the open/close transition since it.
wait screenshot <path>Registers the capture at the wait’s arm and releases only once the PNG is written — so the captured frame is the state as of the wait’s batch, and the queue continues only after the capture exists. Windowed only: headless fails the script immediately (screenshot <path> without wait stays the asynchronous next-frame capture).
… timeout=<duration>After any wait but a duration: how long it may take. A capture that can never complete fails loudly at its timeout= (the default) instead of hanging.
play <file>Runs the file’s lines next.
screenshot <path>Saves the next drawn frame as a PNG — windowed the next presented frame (eventually consistent); headless the run renders one offscreen frame of the current state at the capture’s tick.
start-video <path>Records to an .mp4 from the next frame (window only).
stop-videoWrites the recording.
echo <text>Prints [script] <text> — a marker in the log.
esc, save, load, exitThe pause menu, save, load, quit.
camera <x> <y>Moves the view (a debug jump).

A chapter of a walkthrough:

wait idle timeout=60s          # the intro
click ui verbPick
click actor deskPapers
wait var crime::clues == 1
wait idle
click ui verbTalk
click actor officer
wait idle                      # the dialogue options
click ui "What happened here?"
wait said "Open and shut"
exit

The pause menu

The ESC overlay is a ui block the engine ships with every game — dimmed, with three items a grid renders from the engine’s options:

ui optionsMenu
    quad color=0,0,0,0.3
    grid items=$options cols=1 anchor=center padding=20
        text $item.label click=$item.callback

save / load write and restore all dynamic state — variables, open panels, scripts parked mid-line — so a walkthrough can round-trip a save and keep playing identically.

Video

start-video <path> records the canvas at twice its size — 1280x960 for a 640x480 game — whatever the window size, at up to 60 frames a second, with the game’s sound, as an .mp4 (an existing file is replaced). Recording runs in real time with the window; stop-video, exit, a failing script or closing the window writes the file.

(echo "start-video target/run.mp4"; cat walkthrough.play) | ADVC_STDIN=1 ./target/debug/my-game

Everything drawn in the canvas is recorded.

Building with advc --release

advc --release builds the same game into target/release/, optimized, and packs every asset the game uses into one file next to the executable — the deliverable form, ready to zip and share. Behavior is identical to the debug build.
